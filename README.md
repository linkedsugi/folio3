# RoleFit Canvas (롤핏 캔버스)

> 지원할지 말지, 부서장의 눈으로 먼저 판단하세요.

취준생의 **지원 판단** 웹앱입니다. 채용 공고(JD)와 내 이력을 넣으면

1. **결과물 1 · 부서장이 뽑으려는 사람** — JD를 항목의 목록이 아니라 한 사람의 해체도로 읽어, 이 부서의 실제 일 · 그 일을 해낼 사람의 상 · 각 항목이 담보하려는 실제 능력을 복원합니다.
2. **결과물 2-1 · 기본 이력서** — 내 이력을 그대로 정리하고 JD 요소별 액면 충족률(예: 60%)을 냅니다.
3. **결과물 2-2 · 스토리보완 이력서** — 항목을 그대로 못 채워도 부서장이 담보하려던 능력을 다른 경험으로 갈음할 수 있음을 논증합니다. 갈음 주장마다 이력 원문 인용 근거가 붙고, **근거 없는 주장은 점수에 반영하지 않습니다.**
4. **결과물 3 · 목표 이력서** — 합격선 80%까지 무엇을 보강해야 하는지 네 갈래(① 발굴 ② 구체화 ③ 학습·프로젝트 ④ 단기 대체 불가 + 대안 경로)로 정리하고, 체크리스트 → 재분석 루프를 제공합니다.

최종 판정은 **지원 · 보류(목표 이력서 완성 후 지원) · 비추천** 중 하나이며, 스토리보완 충족률 기준으로 코드가 결정적으로 계산합니다 (≥80 지원, 60–79 보류, <60 또는 단기 대체 불가 필수 요건 미충족이면 비추천).

## 실행

```bash
pnpm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 입력
pnpm dev                     # http://localhost:3000
```

- `ANTHROPIC_API_KEY`가 없으면 **데모 모드**로 동작합니다. 내장 샘플(Intel · Gaming Application Engineer 공고 + 게임사 경력 없는 그래픽스 전공자)로 전체 흐름을 체험할 수 있고, 실제 JD/이력 분석은 503으로 안내합니다.
- `ROLEFIT_MODEL`로 모델을 바꿀 수 있습니다 (기본 `claude-fable-5-1`).

```bash
pnpm typecheck   # tsc
pnpm lint        # eslint
pnpm build       # next build
CHROME_PATH=/path/to/chrome pnpm smoke   # Playwright 스모크 (dev 서버가 3000 포트에 떠 있어야 함)
```

## 구조

```
src/app/
  page.tsx                 랜딩 — 약속 · 샘플 미리보기 · 지금 vs 거치면 · 요금 티저
  analyze/                 입력 (JD + 이력, 형식 무관) · 4단계 진행 화면 (스트리밍)
  result/[id]/             결과 화면 — 판정 헤더 → 결과물 1 → 2-1 → 2-2 → 3 → 다음 행동
  result/[id]/resume/      스토리보완 이력서 인쇄용
  history/                 내 공고 대시보드 (브라우저 저장)
  pricing/                 요금 (출시 예정가 · 결제 미연동 안내 · 베타 크레딧)
  method/                  판단 방식 (통찰 메모 요약)
  api/analyze/route.ts     POST: NDJSON 스트리밍 4단계 분석 / GET: 서버 모드
src/lib/
  types.ts                 데이터 모델 (결과물 1 · 2-1 · 2-2 · 3 · 판정)
  schemas.ts               Claude 구조화 출력용 zod 스키마 (단계별)
  ai/prompts.ts            부서장 관점 시스템 프롬프트 + 4단계 프롬프트
  ai/pipeline.ts           실제 분석(Claude) / 데모(샘플 재생)
  assemble.ts              점수·판정 조립, 인용 근거 원문 검증, 보강 항목 영향도 계산
  scoring.ts               가중 충족률, 냉정함의 규칙, 판정 규칙, 네 갈래 메타
  sample.ts                내장 데모 샘플 (액면 60% → 스토리보완 72% → 보류)
  storage.ts / useStorage.ts  localStorage 저장 + 구독 훅, 베타 크레딧
```

## 냉정함이 코드로 강제되는 지점

- **점수는 LLM이 아니라 코드가 계산**합니다. 모델은 항목별 충족 수준과 근거 인용만 내고, 가중합·판정·보강 영향도는 `scoring.ts` / `assemble.ts`가 결정적으로 계산합니다. 결과 화면의 "점수 산출표"와 항상 일치합니다.
- **인용 검증**: 갈음 논증의 근거 인용문이 이력 원문에 실제로 없으면 근거로 인정하지 않고 "미반영"으로 표시합니다 (`quoteFound`).
- **갈음 상한**: 근거가 `grounded`일 때만 액면 수준을 올릴 수 있고, 단기 대체 불가 요건(자격·학위 등)은 갈음하지 않습니다.
- **JD 분석은 이력을 보지 않습니다** (1단계는 JD만 입력) — 지원자에 맞춰 JD 해석이 휘는 것을 막습니다.

## 수익화 (정직한 게이팅)

- 첫 공고 1건은 **전부 무료**. 두 번째 공고부터 결과물 1 · 2-1은 무료, 결과물 2-2 · 3 · 판정은 크레딧으로 엽니다.
- 결제는 아직 연동되지 않았습니다. 베타 기간에는 **베타 크레딧 5개**(모두 쓰면 매일 1개 충전)로 열 수 있으며, 요금 페이지의 금액은 모두 "출시 예정가"로 표시됩니다. 가짜 결제창·가짜 후기·합격 보장 문구는 두지 않습니다.
- 모든 결과·크레딧 상태는 브라우저 `localStorage`에만 저장됩니다 (서버 DB 없음).

## 배포
