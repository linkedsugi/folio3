# RoleFit Canvas (롤핏 캔버스) — 최종 빌드 스펙 v1.0

기준 문서: 「RoleFit Canvas 통찰 메모」(MindCanvas, 2026-09-13). 이 문서는 네 개의 관점 스펙(motivation-ux · monetization · ia-screens · scoring-ai)과 세 심사 노트를 하나로 합친 **단일 진실 문서**다. 엔지니어는 이 문서만으로 빌드한다. 메모 용어를 그대로 쓴다: 「부서장이 뽑으려는 사람」(결과물 1) · 기본 이력서(결과물 2-1) · 스토리보완 이력서(결과물 2-2) · 목표 이력서(결과물 3) · 액면 충족률 · 스토리보완 충족률 · 갈음 논증 · 근거 · 반영/미반영 · 합격선 80% · 판정 = 지원 · 보류(목표 이력서 완성 후 지원) · 비추천.

기술 전제: Next.js 16 (App Router) + Tailwind v4 · Anthropic Claude 백엔드(`@anthropic-ai/sdk`) · DB 없음(localStorage) · `ANTHROPIC_API_KEY` 없으면 데모 모드(내장 샘플 재생) · 결제 미연동(가격·게이팅 UI만 정직하게 표시).

## 1. 제품 한 줄 정의와 핵심 약속

**한 줄 정의**
> RoleFit Canvas는 채용 공고와 내 이력을 넣으면, 뽑는 부서장의 눈으로 JD를 읽어 「부서장이 뽑으려는 사람」을 복원하고, 내 경험으로 그 역할을 해낼 수 있다는 근거를 세운 뒤, 합격선 80% 기준으로 **지원 · 보류 · 비추천**을 판정하는 취준생용 웹앱이다.

**두 원칙(메모 그대로)**
- 원칙 1. JD는 뽑는 부서장의 관점에서 바라본다. 지원자의 눈으로 항목을 맞추지 않는다.
- 원칙 2. 이력서는 뽑는 부서장이 원하고 좋아하는 이력서를 쓴다. 내가 쓰고 싶은 것을 쓰지 않는다.

**핵심 약속 5개(랜딩·결과·요금 화면에서 반복 사용)**
1. JD를 항목의 목록이 아니라 한 사람의 해체도로 읽는다 → 결과물 1.
2. 액면 충족률과 스토리보완 충족률을 분리해 보여준다. 액면 숫자만 단독으로 크게 보여주지 않는다.
3. 갈음 주장마다 이력 속 실제 경험이 근거로 붙는다. 근거 없는 주장은 점수에 반영하지 않는다.
4. 판정은 스토리보완 충족률로 내리며, 합격선은 80%다.
5. 합격선에 못 미치면 무엇을 채우면 몇 %p가 오르는지(예상)를 네 갈래로 보여준다.

**하지 않는 것(코드베이스에 존재하면 안 되는 것)**: 자소서 자동 생성 · 합격 보장/합격률 확정 수치 · 근거 없는 점수 올리기 · 가짜 후기·사용자 수 · 가짜 결제창 · 실제 진행과 무관한 프로그레스바.

**Aha Moment 정의(계측 기준)**: 한 화면에서 (a) 액면 충족률이 낮고 (b) 스토리보완 충족률이 올라갔으며 (c) 「미반영 · 근거 부족」 배지가 1개 이상 보이는 순간. 이벤트 `aha_viewed` = 결과물 2-2 섹션이 뷰포트 50% 이상 2초 노출 AND 반영 배지 1개 이상 렌더.

## 2. 정보구조 / 라우트

### 2.1 라우트

| 경로 | 역할 | 비고 |
|---|---|---|
| `/` | 랜딩 | 샘플 결과 미리보기 포함 |
| `/analyze` | 분석 입력 + 분석 진행(오버레이) | `?from={id}`: 재분석(JD 유지, 이력 보강) |

| `/api/analyze` | POST · SSE 스트리밍 | 데모 모드면 fixture를 단계당 1.2초 지연으로 재생 |

- 베타 배지(헤더 우측 작게): 「베타 · 후기 수집 전」

### 2.3 핵심 흐름
```
/ → [첫 분석 무료로 시작하기] → /analyze (붙여넣기 2회 또는 샘플 채우기)
  → [부서장의 눈으로 분석하기] → 4단계 진행 오버레이 (SSE)
  → /result/{id} (판정 + 세 숫자 → 결과물 1 → 2-1 → 2-2 → 3 → 다음 행동)
  → 결과물 3 체크리스트 채움 → [보강 내용 반영해서 다시 분석하기] → /analyze?from={id} → 새 결과(변화 표시)
  → /history 에서 공고별 판정·추이 확인
두 번째 공고부터: 결과물 1·2-1·숫자·판정 무료 → GateCard → 베타 크레딧으로 열기 / 요금 보기
```

## 5. 점수 로직

### 5.0 다섯 규칙
| # | 규칙 | 구현 |
|---|---|---|
| R1 | 점수는 LLM이 아니라 코드가 계산한다 | LLM 출력 스키마에 점수·퍼센트 필드 없음. 레벨은 열거형. 가중합·판정·expectedGain은 서버 코드 |
| R2 | 근거 없는 주장은 0 | 모든 `Evidence.quote`는 `resumeNormalized`의 연속 부분 문자열이어야 한다. 검증 실패 → `verified=false` → 레벨 강등 · 미반영 |
| R3 | JD 분석(1단계)은 이력을 보지 않는다 | 1단계 요청 페이로드에 `resumeText` 미포함(테스트로 강제) |
| R4 | 갈음은 항목 문구가 아니라 `intendedAbility`를 향한다 | 3단계 논증의 `intendedAbility`가 1단계 값과 다르면 코드가 덮어쓰고 검토 플래그 |
| R5 | 상한이 있다 | 근거 강도 상한 × 대체 가능성 상한. 근거 강/중/약 판정 자체는 LLM이 하고 코드는 검증 통과 인용 중 최대치를 취한다(정직하게 문서화) |

### 5.1 가중치
`weight = kindWeight × importanceWeight` — 필수 2 · 우대 1 / 핵심 3 · 중요 2 · 보조 1 → {6, 4, 2, 3, 2, 1}. 핵심은 최대 4개(초과 시 코드가 importance 순으로 강등). `totalWeight = Σ weight`.

### 5.2 액면 충족률 (결과물 2-1)
- `faceLevel ∈ {0, 0.5, 1}`. 항목 문구를 문자 그대로 적용(경력 5년 → 게임회사 경력 없으면 0, 4년이면 0.5).
- 0.5·1은 검증된 `facts` 1개 이상 필수. 없으면 코드가 0으로 강등하고 `reason` 앞에 「[근거 미확인으로 0 처리]」.
- `faceScore = Σ(faceLevel × weight) / totalWeight × 100`.

### 5.3 갈음 논증 반영 규칙 (결과물 2-2) — 근거 필수
근거 강도(검증 통과한 인용 중 최대):

| 강도 | 조건 | 갈음 후 상한 |
|---|---|---|
| 없음 | 검증 통과 인용 0개 | **미반영**(액면 유지) · 사유 「근거 없음 — 미반영」 |
| 약 | 활동·관심 언급만, 역할·산출물·결과 없음 | 0.5 |
| 중 | 역할·기간·산출물 중 2개 이상 명시 | 0.75 |
| 강 | 정량 결과 + 본인 역할 + 검증 가능한 산출물 | 1.0 |

대체 가능성 상한: 갈음가능 1.0 · 조건부 0.75 · 대체불가 = 갈음 금지(액면 유지). 조건부는 경력 연수·규모 요건 등 "표지" 항목, 대체불가는 법정 자격·면허·학위 필수 명시·비자·근무지·병역·출장 가능 여부 등 제도 요건에만.

- `appliedLevel = max(faceLevel, min(proposedLevel, 근거상한, 대체가능성상한))`
- `counted = appliedLevel > faceLevel`. 아니면 `notCountedReason` ∈ {「근거 없음 — 미반영」, 「근거 약함 — 상향 없음」, 「대체불가 항목 — 갈음 불가」, 「제안 레벨이 액면 이하」, 「담보 능력과 무관」}
- `storyLevel = appliedLevel`(논증 없는 항목은 faceLevel). `storyScore = Σ(storyLevel × weight) / totalWeight × 100`.
- 항목당 논증 1개. 액면 1인 항목은 논증 생성 금지. 같은 사실을 여러 항목에 써도 강도는 항목별 판정.

### 5.4 합격선 80%와 판정 규칙 (우선순위 순)
| 조건 | 판정 |
|---|---|
| 필수 & 대체불가 항목 중 `storyLevel = 0` 존재 | **비추천** (`hardFail` 기록, 결과물 3 ④에 대안 경로 필수) |
| `storyScore ≥ 80` (반올림 전 값) | **지원** |
| `storyScore < 80` AND 권장 경로 `projectedScore ≥ 80` | **보류** (목표 이력서 완성 후 지원). 내부 `reachableBy`: 최소 경로(①+②)로 ≥80이면 `"min"`, 아니면 `"recommended"` |
| `storyScore < 80` AND 권장 경로로도 < 80 | **비추천** (결과물 3은 생성해 대안 경로·장기 경로를 보여준다) |

- 합격선 80은 메모의 상수. 사용자 변경 불가(설정 UI 없음).
- 표시는 반올림 정수, 판정은 반올림 전 값(79.6 → 표시 「79.6%」로 소수 병기, 판정 보류).

### 5.5 결과물 3 — 네 갈래 보강 구분과 예상 상승폭
| 갈래 | 판별 조건 | 행동 타입 | 산출물 | 기간 | 점수 |
|---|---|---|---|---|---|
| ① 이미 있는데 드러나지 않은 경험 | 이력의 사실이 이 능력을 전제하는데 방법·수치·역할이 없음 | 질문확인(2~4개) → 답변을 이력에 추가 → 재분석 | 보강된 이력 문장 | 1일~1주 | `expectedGain` (조건부 표시) |
| ② 관련은 있지만 근거가 약한 경험 | 갈음 논증이 있으나 강도 약·중으로 상한에 걸림 | 자료보완(링크·캡처·수치·보고서) | 포트폴리오 항목 1개 | 1~3주 | `expectedGain` |
| ③ 실제로 부족한 역량·경험 | faceLevel 0/0.5, 갈음 근거 없음, 갈음가능·조건부 | 학습·프로젝트·현장 경험 설계(산출물 나오는 프로젝트 1개) | 공개 산출물 | 4~12주(장기는 12주+) | `expectedGain` |
| ④ 단기간에 대체하기 어려운 요건 | 대체불가 & 미충족, 또는 조건부 상한(0.75) 위 부분 | 대안경로(미충족 명시 + 인접 직무/다른 트랙/재도전 시점 2~3개) | 대안 공고 유형 | 1~3년 | **+0** |

- `expectedGain(%p) = (targetLevel − currentLevel) × weight / totalWeight × 100`, 소수 1자리. UI 라벨 반드시 「예상 +N%p」. ①은 「(조건부)」 병기.
- 코드가 `targetLevel` 상한 강제: 조건부 ≤ 0.75, 대체불가 = 현재 유지, ③ ≤ 1.
- 경로: **최소 경로** = ①+② / **권장 경로** = ①+② + ③ 중 `durationWeeks ≤ 12` / **장기 경로** = 전부. 각 경로의 `projectedScore`는 pts 합으로 계산(반올림된 %p 합산 금지).
- 체크리스트 진행 예상치: 「채움」 상태 항목의 expectedGain 합을 pts로 환산해 「예상 {n}%」.

### 7.2 단계 1 · 부서장 관점 JD 분석 → 결과물 1
- 입력: `company`, `jobTitle`, `jdText`만.
- 시스템 프롬프트 요지: 「당신은 이 포지션을 뽑는 부서장이다. 인사팀도 지원자도 아니다. 부서에 실제 일이 하나 있고 그 일을 해낼 사람이 필요해서 능력을 항목으로 풀어 적은 것이 JD다. 항목을 다시 한 사람으로 조립하라. (1) 실제 일 (2) 사람의 상 한 문장 (3) 부서장이 이력서에서 답을 찾고 싶은 질문 3~5개 (4) 각 항목이 담보하려는 실제 능력과 충족으로 볼 증거. 항목마다 필수/우대, 핵심/중요/보조(핵심 최대 4개), 갈음가능/조건부/대체불가를 정하라. 경력 연수·학위·자격·비자·근무지 같은 숫자·제도 요건은 무엇을 담보하려는지 반드시 풀어 쓰되, 법정·제도 요건만 대체불가로 표시하고 경력 연수는 조건부로 표시하라. JD에 없는 것을 추정하면 assumptions에 적어라. 퍼센트·점수는 쓰지 말라.」
- 출력: §6.3·6.4 스키마(weight 제외).
- 가드레일·후처리: weight 계산 · 핵심 4개 초과 강등 · 항목 6개 미만이면 `verify` 경고(진행 허용).

### 7.3 단계 2 · 기본 이력서 매핑 → 결과물 2-1
- 입력: 1단계 `items`(id, label, kind, importance, evidenceExpected), `resumeNormalized`.
- 시스템 프롬프트 요지: 「이력을 형식 그대로 정리하라. 미화·추론·추가 금지. 각 JD 항목에 대해 항목 문구를 문자 그대로 적용해 0/0.5/1을 매기고, 0.5·1이면 이력 원문에서 한 글자도 바꾸지 말고 8~300자를 연속으로 복사한 quote를 붙여라. 인용할 문장이 없으면 0이다.」
- 출력: §6.6.
- 가드레일·후처리: 인용 정확 매치 검증(§7.6) → 미검증 시 0 강등 → `faceScore` 계산 → `unusedFacts` 초안.

### 7.4 단계 3 · 스토리보완 → 결과물 2-2
- 입력: 1단계 전체, 2단계 mappings, `resumeNormalized`, 코드가 계산한 faceScore·ScoreSheet rows, 갈음 규칙 표(§5.3) 텍스트.
- 시스템 프롬프트 요지: 「당신은 이 지원자를 위해 부서장이 읽고 싶은 이력서를 쓰는 사람이다. 독자는 부서장이다. 액면 1 미만이고 대체불가가 아닌 항목마다, 항목 문구가 아니라 intendedAbility를 향해 '이 능력은 ○○로 갈음된다'는 논증을 1개 세우고 이력 원문에서 그대로 복사한 근거를 붙여라. 근거마다 강/중/약을 정직하게 매기고(정량 결과+역할+산출물=강, 역할·기간·산출물 중 2개=중, 언급뿐=약), 근거가 없으면 evidence: []로 두고 그 사실을 적어라. proposedLevel은 근거 상한을 넘기지 말라. 그다음 부서장 질문 순서대로 섹션을 구성하고 각 bullet은 근거 ref를 갖는다. 근거 ref가 없는 bullet은 쓰지 말라. 퍼센트·점수는 쓰지 말라.」
- 출력: §6.7·6.8.
- 가드레일·후처리: 인용 검증 → `evidenceStrength` 재계산(검증 통과 최대치) → `appliedLevel`/`counted` → `storyScore` → evidenceRefs가 전부 미검증인 bullet 삭제(로그) → `intendedAbility` 불일치 덮어쓰기.

### 7.5 단계 4 · 목표 이력서 + 판정 문장 → 결과물 3, Verdict
- 입력: 1~3단계 결과, ScoreSheet(읽기 전용), 코드가 미리 계산한 `decision` 후보 규칙(§5.4), 카테고리 규칙(§5.5).
- 시스템 프롬프트 요지: 「점수는 이미 계산되어 있다. 바꾸지 말고 숫자를 쓰지 말라. 당신의 일은 (1) storyLevel < 1인 항목마다 카테고리 ①~④ 중 하나를 정하고 행동을 설계하는 것(①은 질문 2~4개, ②는 어떤 자료를 어떻게, ③은 산출물이 나오는 프로젝트 1개와 기간(주), ④는 미충족 명시와 대안 경로 2~3개), (2) targetLevel을 정하는 것(조건부 0.75 초과 금지, 대체불가는 현재 유지), (3) 보강 후 제출할 이력서 개요, (4) 판정 이유 2~3문장과 다음 행동 한 문장. 위로·격려 문구를 쓰지 말라. 항목과 사실로 말하라.」
- 출력: §6.9·6.10 + `verdict.headline/reasons/nextAction`(decision은 코드가 채움).
- 가드레일·후처리: targetLevel 상한 강제 → expectedGain·paths·projectedScore 계산 → Verdict 확정(§5.4) → 감정 문구 검출(「충분히」「분명히」「자신 있게」「가능성이 높습니다」「걱정 마세요」) 시 1회 재요청 → 세션 저장(`done`).

### 8.4 「왜 돈을 받나요」 본문
- **판단에 값을 매깁니다.** 이력서 첨삭이 아니라, 이 공고에 지원할지 말지의 판단과 그 근거를 드립니다.
- **근거 없는 점수는 팔지 않습니다.** 이력에서 근거를 찾지 못한 주장은 점수에 넣지 않습니다. 그래서 80%는 희망이 아니라 판단입니다.
- **보강하면 다시 재봅니다.** 보류 판정을 받았다면, 목표 이력서를 채우고 같은 크레딧으로 다시 분석할 수 있습니다.

### 8.5 FAQ 6문항
1. 첫 공고는 정말 전부 무료인가요? — 네. 결과물 1·2-1·2-2·3과 최종 판정, 재분석 3회를 모두 쓸 수 있습니다.
2. 두 번째 공고부터 무료로 볼 수 있는 건 무엇인가요? — 「부서장이 뽑으려는 사람」, 기본 이력서와 액면 충족률, 스토리보완 충족률과 판정입니다. 갈음 논증의 근거, 제출용 이력서 본문, 목표 이력서는 크레딧이 필요합니다.
3. 지금 결제할 수 있나요? — 아니요. 결제 기능은 준비 중이며, 베타 기간에는 무료 베타 크레딧 3개가 제공됩니다.
4. 충족률이 합격을 보장하나요? — 아닙니다. 부서장 관점의 추정이며, 근거가 확인된 항목만 반영한 보수적인 수치입니다.
5. 내 이력과 JD는 어디에 저장되나요? — 브라우저(localStorage)에만 저장됩니다. 서버 데이터베이스에 보관하지 않습니다. 분석 시에만 AI 모델에 전송됩니다.
6. 재분석은 무엇인가요? — 목표 이력서의 보강 항목을 채운 뒤 같은 공고를 다시 분석하는 것입니다. 공고 1건당 3회가 포함됩니다.

- 차분하되 확신. 판단을 내리는 도구. 장식·이모지·과장 없음. 느낌표 금지.
- 문체: 「~합니다」 존댓말, 짧은 문장. 사용자를 「취준생」이라 부르지 않고 「당신/내」로. 합격 보장·순위·경쟁률 언급 금지.
- 숫자에는 항상 맥락. 미래 점수에는 반드시 「예상」. 냉정한 문장 다음 줄에는 반드시 「할 수 있는 다음 행동」.

### 11.2 판정 마이크로카피(고정 구조: 판정 단어 → 근거 숫자 → 다음 행동)
**지원**(녹)
- 헤더: 「스토리보완 {story}% · 합격선 80%를 넘었습니다. 지원할 이유가 있습니다.」
- 부연: 「근거가 붙은 논증만으로 합격선을 넘었습니다. 아래 스토리보완 이력서를 부서장이 읽고 싶은 순서 그대로 제출하세요.」
- 주 버튼 「스토리보완 이력서 복사하기」 / 보조 「그래도 목표 이력서로 더 올리기」

**보류**(호박) + 부제 「목표 이력서 완성 후 지원」
- 헤더: 「스토리보완 {story}% · 합격선까지 {gap}%p. 지금은 아니지만, 길은 있습니다.」
- 부연: 「아래 목표 이력서의 ①②만 채워도 예상 {projectedMin}%, ③까지 채우면 예상 {projectedRecommended}%입니다. 이 공고는 보강하면 지원 가능한 포지션입니다.」
- 주 버튼 「목표 이력서 체크리스트 시작하기」 / 보조 「보강 내용 반영해서 다시 분석하기」(체크 1개 이상 시 활성)

**비추천**(회색) — 3문장 고정
1. 판정의 범위: 「이것은 당신의 역량이 아니라, 이 공고와 지금 이력의 거리에 대한 판정입니다.」
2. 이유의 구체성: 「{hardFail이면: 필수 요건 "{label}"은 단기간에 대체하기 어렵고, 갈음할 근거가 이력에 없었습니다. / 아니면: 권장 경로(12주)로도 예상 {projectedRecommended}%로 합격선에 미치지 못합니다.}」
3. 다음 행동: 「④의 대안 경로를 보거나, 결과물 1에서 복원한 '부서장이 뽑으려는 사람'에 더 가까운 공고를 찾아보세요. 이 판정으로 지원서 한 장 쓰는 시간을 아꼈다면, 그 시간은 ③에 쓰세요.」
- 주 버튼 「④ 대안 경로 보기」 / 보조 「이 역할에 맞는 다른 공고 분석하기」(`/analyze`, 상단에 personImage 메모 자동 표시). 비추천에서도 2-2·3 전부 제공(숨기지 않음).

### 11.3 장치 목록
1. **체크리스트 → 재분석 루프**: GapItem 상태 3단 + 답변/메모 → 「보강 내용 반영해서 다시 분석하기」 → `[보강 추가]` 자동 병합 → 재분석 헤더 「스토리보완 70% → 79% (+9%p) · 합격선까지 1%p」 → 판정 변경 배너.
2. **예상 진행 게이지**: 「현재 70% → 채운 항목 반영 시 예상 76%」(코드 계산, 「예상」 라벨).
3. **항목 채움 토스트**: 「근거 하나 추가됨. 재분석하면 점수에 반영됩니다.」
4. **히스토리 궤적**: 카드에 「60 → 70 → 79」, StatsStrip 「평균 액면 58% → 스토리보완 71%」 — "논증이 올린다"의 증거.
5. **재방문 배너**(/history): 「{회사} · {직무} — 채운 항목 2/5. 남은 항목을 채우면 예상 80%.」
6. **보수성 지표**: 「이번 분석에서 점수 미반영 처리된 주장: 3건」 — 숫자를 믿게 하는 장치.
7. **점수 산출표 펼치기**: 「어떻게 계산했나요?」 — 합계가 화면 %와 일치.
8. **내 판정 이력이 사회적 증거**: 비추천이 섞인 본인 통계(가짜 후기 대신).
9. **헤더 도피로**: 「80%까지 무엇이 필요한지 바로 보기 ↓」.
10. **unusedFacts 피드백**: 부서장이 안 보는 정보를 알려줘 ①로 끌어올릴 기회.
11. **두 번째 공고 이력 자동 불러오기** + 확인 문구 「지난 공고에서 보강한 항목이 이력에 반영되었나요?」
12. **비추천의 효용 프레이밍**: 시간을 아꼈다는 문장 + 다른 공고 분석으로 연결.
13. **첫 공고 재분석 3회 무료 유지**: 게이트 밖에 두어 리텐션 루프가 끊기지 않게.

## 12. 완료 기준 체크리스트
1. `/result/{id}`가 그림 4 순서(헤더+판정 → 1 → 2-1 → 2-2 → 3 → 최종 판정)를 400px에서 가로 스크롤 없이 렌더링한다.
2. ScoreMeter가 어디서든 액면·스토리보완·합격선 세 값을 함께 표시하고, 액면 숫자 단독 강조가 없다.
3. JdItemCard가 ① 액면 ② 갈음 논증+근거 칩 ③ 반영/미반영을 모두 보여주고, 미반영이 숨겨지지 않으며 합계에서 제외된다. 「액면 ○ → 갈음 ○ (근거 강도 · 상한)」 분해 표시.
